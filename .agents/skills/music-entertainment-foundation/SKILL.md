# 音乐娱乐领域知识包

## 领域标识

- `domain_id`: `music_entertainment`
- `skill_name`: `music-entertainment-foundation`
- aliases: `music`、`entertainment`、`音乐`、`音乐娱乐`、`音乐人物`、`娱乐人物`
- 注册表：`.agents/skills/domain-foundation-registry.json`

通用流程 skill 应优先通过注册表加载本知识包；不要在通用 skill 中写死本路径。

## 使用时机

当任务对象属于音乐娱乐领域时使用，包括歌手、乐队、专辑、歌曲、音乐纪录片、音乐人物、娱乐人物、音乐主题和音乐背景故事。

本技能只提供领域判断，不直接执行研究、选题、大纲或写作。

## 目标

把音乐娱乐领域的稳定判断注入上层流程，帮助代理判断：

- 哪些材料能进入主线。
- 哪些材料只能作为背景。
- 哪些材料容易八卦化、粉丝滤镜化、苦情化。
- 选题是否成立。
- 段落是否写偏。
- 写作是否变成资料堆砌、怀旧煽情或术语堆砌。

## 人物传记落点

人物传记不默认落到音乐本体。音乐本体是可选落点之一，不是唯一正确答案。

当 `task_object` 是人物时，上层流程应先根据研究资料包和用户目标判断本次传记的主要落点，可选方向包括：

- 音乐本体：作品、唱法、创作方法、制作审美、曲风演变。
- 职业弧线：出道、转折、低谷、重建、晚期阶段或行业位置变化。
- 公众形象：外界标签、误读、声誉变化、被记住或被忽略的原因。
- 关系因果：合作关系、厂牌、制作团队、市场环境、地域文化。
- 价值观与行动：信仰、性格、选择、组织方式如何影响作品或职业决定。
- 时代位置：某个审美、行业阶段或文化语境里，他/她为什么特殊。
- 生命阶段：疾病、年龄、告别、遗作、纪念，但必须避免苦情化消费。

选择落点时必须写清：

- 为什么这个落点比其他落点更适合当前人物。
- 哪些材料支持这个落点。
- 如果强行落到音乐本体，会不会遮蔽人物真正值得讲的部分。
- 如果完全离开作品和职业证据，会不会滑向八卦、鸡汤或人物标签化。

## 输入

- `task_object`：人物、歌曲、专辑、主题或事件。
- `content_type`：音乐赏析、音乐人物传记、娱乐人物传记、音乐背景故事、音乐主题盘点之一。
- `stage`：research、topic、outline、write、review 之一。
- `research_pack`：可选，研究阶段之后形成的资料包。
- `selected_topic`：可选，选题阶段之后确定的题目。

## 可读取参考

- `references/stable_cards.json`：20 张稳定领域能力卡，供机器读取。
- `references/stable_cards.md`：20 张稳定领域能力卡，供人工审查。
- `references/card_audit.md`：第一轮候选卡到稳定卡的审查记录。
- `references/collection_map.json`：音乐娱乐领域采集地图，供 `research-collector` 生成领域特定采集任务。

## 领域渠道提示

研究阶段由 `references/collection_map.json` 按对象类型注入特定渠道；不要在通用采集脚本中硬编码音乐娱乐规则。

采集地图覆盖：

- 人物：官方资料、作品/歌曲入口、专业乐评、公众接受度。
- 歌曲：发行制作、歌词/MV/现场、网易云等评论接受度。
- 专辑：发行制作、曲目结构、豆瓣长评/短评、专业乐评。
- 选题方向：验证事实、作品、评论和接受度是否支撑该方向。

渠道原则：

- 歌曲/专辑：网易云音乐评论可用于听众记忆、传播场景、情绪入口和接受度判断。
- 专辑/纪录片/传记片：豆瓣长评和短评可用于观点结构、观众判断和接受度判断。
- 发行、曲目、制作、巡演、奖项等事实：优先使用唱片公司、流媒体平台、艺人官方渠道、权威资料库和主流媒体。

评论材料只作接受度和情绪证据，不作事实来源。不得复制评论语言进入成稿。

## 使用方法

1. 根据 `content_type` 读取 `stable_cards.json` 中的 `direction_map`。
2. 只选择与当前任务最相关的 3-7 张稳定卡，不得全量注入。
3. 对每张被选中的稳定卡，提取：
   - `stable_id`
   - `name`
   - `capability`
   - `when_to_use`
   - `how_to_apply`
   - `video_paragraph_use`
   - `failure_pattern`
4. 研究阶段只用稳定卡决定资料分类和风险标注，不生成选题。
5. 选题阶段只用稳定卡判断角度是否成立、风险是什么、需要补哪些材料。
6. 大纲阶段把每段绑定 1-2 张稳定卡，并写清该段解决的问题。
7. 写作阶段只接收大纲阶段选定的少量稳定卡，不重新读取全部稳定卡。
8. 审稿阶段用 `failure_pattern` 检查是否出现流水账、资料堆砌、粉丝滤镜、苦情化、术语堆砌或八卦化。

## 输出

本技能本身不单独输出成品。被上层技能调用时，应输出一个 `foundation_use` 区块：

```json
{
  "domain": "music_entertainment",
  "content_type": "音乐人物传记",
  "selected_cards": [
    {
      "stable_id": "stable_009",
      "name": "传记截断判断",
      "use_reason": "本题不能按完整生平写，需要先限定阶段。",
      "failure_pattern": "会变成百科时间线，看似完整，但每段都浅。"
    }
  ]
}
```

## 合格检查

- 通过：只选取 3-7 张相关稳定卡，并能说明选择理由。
- 通过：每个判断都能落到资料取舍、选题成立、段落组织或审稿风险。
- 通过：评论材料和事实材料分开。
- 警告：选取超过 7 张稳定卡，容易让生成变重。
- 警告：只引用卡名，没有说明如何用于当前对象。
- 失败：把稳定卡当成固定模板或固定句式。
- 失败：复制样本文字或长证据进入成稿。

## 禁止事项

- 不直接生成选题。
- 不直接写正文。
- 不追娱乐新闻、综艺八卦、饭圈争吵。
- 不把 20 张稳定卡全部塞入写作提示。
- 不把听众评论当成金句库复制。
- 不用“过气”“翻红”“塌房”“封神”等标签支配人物判断。
- 不用背景资料替代作品和人物判断。

## 失败处理

- 如果对象不属于音乐娱乐领域，停止使用本知识包，改由上层流程选择其他领域知识包。
- 如果 `content_type` 不明确，先让研究或选题阶段判断内容类型，不要直接调用写作。
- 如果稳定卡无法覆盖当前对象，标记 `foundation_gap`，说明缺少哪类领域经验，再决定是否补采样本。

## 是否回写经验

本技能不直接回写经验。测试后如需沉淀新经验，应由上层流程写入项目规定的经验库或样本库，并经过人工确认后再升级为稳定卡。
