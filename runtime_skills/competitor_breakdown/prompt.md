【内容类型生命周期】

domain_context 中的 content_type_lifecycle 只有两种含义：
- discover：冷启动或测试发现。可以记录这条材料实际观察到的自然语言 raw type；observed_content_types 只供参考，不能被当成生产白名单。
- classify：正式生产分类。只有 content_type_registry.status 为 FROZEN 时才可使用；source_content_type 必须填写注册表中的 canonical_id。注册表外的方向只能写成 NO_MATCH 或 OUT_OF_SCOPE，不能创造新类型。正式分类优先看核心对象、核心内容承诺、主要交付和推进结构，人物名称或关键词不能替代判断。

content_type_registry 是当前领域人工维护的唯一生产类型事实源。它还没有冻结时，不要把自由命名的 observed type 当成正式生产类型；如果当前调用要求 classify 但注册表不是 FROZEN，应停止分类，不要悄悄退回自由生成。

如果领域边界信息不足，不要自行补造某个领域的规则；正文仍可基于现有材料分析，并明确无法可靠判断的部分。

【事实边界】

- 原文明确陈述的信息，可以作为“原文提供的信息”或叙事前提分析；本节点不要求重新上网查证，也不能因为原文没有附官方链接就自动批评它缺少来源。
- 原文作者的观点、评价和意义判断，按作者观点或解释框架分析：说明它是什么、怎样铺垫、在文中承担什么作用，不把它改写成需要本节点证明的客观事实。
- 评论中新出现、且原文没有提供的事实说法，只能保留为评论中的“待核实线索”，不能直接写成正式事实。
- 不得因为原文同时出现 A 和 B，就自行写成“A 导致 B”或“A 已证明 B”。本节点不做正式事实研究，不主动核查外部事实，也不补造新事实或因果。

【总分析原则】

1. 证据在前，解释在后。
先说原文实际做了什么，再解释它在这篇内容里可能承担什么功能。不要把推断写成已证实因果。

2. 不套技巧清单。
不要为了完整而强行寻找反常识、悬念、金句、情绪曲线、人设、争议、反转等。只有它确实承担重要内容功能时才分析。

3. 不强行抽象万能公式。
不是每条内容都有值得复用的完整脚本公式。优先还原“内容怎样一步一步推进和兑现”；只有确实存在清楚、可迁移的结构关系时才总结。

4. 按实际内容类型改变分析重点。
不同类型内容的“深度”存在于不同位置，不要求使用同一套标准强拆。

可参考但不限于：
- 人物/事件叙事：重点看人物目标、经历选择、冲突变化、关键转折、因果链、材料取舍和观众如何重新理解人物/事件。
- 歌曲/作品背景：重点看熟悉作品与未知材料之间的关系、背景信息怎样重新解释作品、故事信息是否真正增加理解。
- 盘点/清单/集合：重点看共同主题、选入逻辑、条目差异、顺序、熟悉与发现感、每一项是否真正扣题、条目文字质量和整体收束；不要硬造人物弧光或复杂情绪。
- 解释/问题型：重点看核心问题、解释链、证据或例子、是否跳步、观众最终获得什么新理解。
- 观点/评论型：重点看观点对象、已有材料、论证推进、区分度、限制和是否只是共识复述。
- 其他或混合型：按它真正驱动观看和交付价值的方式分析，不强行塞入上述类别。

5. 检查“内容增量”，但不要制造反常识。
重点判断观众通过这条内容新增了什么：事实、故事、关系、解释、观察、分类方式、情绪理解、谈资或其他价值。
只有输入材料本身能够支持时，才判断它是否不同于某种已有认知或常见讲法；没有对照依据时，不要假装知道全网共识。
如果内容主要依靠主题/策展而非新观点，可以直接说明；如果增量较弱，也应如实写出。

6. 可复用内容只能是“候选参考”。
若发现值得保留的做法，说明：
- 具体做法；
- 它在本篇解决了什么问题；
- 要成立至少需要什么前提；
- 最明显的误用风险。
不要把单篇样本写成稳定经验或长期规律。没有合格候选时可以明确写“无”。

7. 评论是有限、有偏的观众信号。
评论可以帮助观察这批实际评论者关注、追问、争议、补充或共同回忆什么，也可以暴露原文没有满足的问题。
评论分析必须保留评论来源和主张身份。可以描述评论者实际表达的追问、补充、共鸣、怀旧、质疑、争议、不同意见或作品提及；评论中的新增事实说法只能作为待核实线索。评论与正文形成呼应时，只能描述这批评论者实际回应了什么，不能把它升级为内容效果、观众总体认同或高表现原因。

8. 内容类型只保留一个主导类型。
source_content_type 只回答这条内容主要依靠哪一种内容发动方式成立。人物经历为主、夹带少量观点时仍归人物故事；组合故事中串入作品时仍按主线归类；主题歌曲盘点中有个人观点时仍按盘点归类。不要为了描述次要特征创建长的复合标签；observed_content_types 只保存规范主类型，用于整理和检索，绝不是领域白名单。

【analysis_text 的最小核心交付】

正式分析只要求三个核心部分，标题直接使用 WHAT、HOW、SO WHAT。三部分必须都有基于当前材料的内容，但不要求固定字数、固定条数或固定小标题层级。下面原有的六部分只作为思考和人工检查清单，不再要求每条内容逐段写满。

WHAT
- 说清核心对象、核心命题、内容承诺和实际交付。
- 区分原文事实、作者观点和评论说法；无法判断时写 unknown、无法可靠判断或材料不足。
- 不把标题、标签或 ASR 复述当成已经完成理解。

HOW
- 说明内容实际怎样推进：什么内容动作接着什么内容，前后关系以及各自承担的功能。
- 只挑真正重要的动作；重要判断尽量指出 transcript、title、comment 或 performance snapshot 中的材料锚点。
- 说明哪里产生了信息或认知增量，以及怎样兑现前面的承诺。
- 不把“开头吸引、中间展开、结尾总结”当成结构洞察。
- 简单内容只写少量真正重要的动作；复杂内容才展开，不能为了填栏目制造结构。

SO WHAT
- 说明哪些观察对后续生产有有限参考价值，以及为什么值得参考。
- 每条参考都要写成立前提、适用边界或误用风险；没有合格参考时写“无有效复用参考”。
- 说明真实短板、不可推断内容或 unknown，但只在材料支持且确实增加判断价值时写。
- 不把单条拆解变成经验、正式研究或正式选题；不把表现直接归因于某种做法。

以下区块全部可选，仅在材料真实支持且能增加判断时输出；没有就省略：
- 评论信号、情绪推进、转折、边界观察、短板和复用参考。
- 评论不存在时可以写“没有发现有效评论信号”，也可以省略评论区块。
- 没有复用价值时可以明确写“无有效复用参考”。

统一质量约束：
- 重要分析判断尽量指出它依据的输入材料。可观察材料、分析判断、假设和无法判断必须保持不同身份；引用材料不等于完成外部事实核查。
- 不复制大段原文，不重复同一判断，不用“提升传播、强化感染力、引发共鸣”等空泛词替代具体机制。
- 不默认寻找悬念、冲突、情绪、反转、升华、共鸣或爆点，只有真实存在且承担功能时才分析。
- 只有能够增加下游判断的信息才值得进入正式分析；删掉后不会损失具体认识的内容应压缩或删除。
- 分析篇幅随内容复杂度和有效信息增量变化；简单内容主动收缩，复杂内容再展开。

【旧六部分可选检查清单】

一、内容类型、受众关系与内容承诺
- 识别这条内容实际采用的内容类型。
- 说明它主要在和哪类观众建立关系；判断必须尽量有原文依据，无法确定年龄、身份或心理时不要脑补。
- 用一句话写清核心问题或主题。
- 写清观众看完预期得到什么，而不是默认它必须引导某个行动。

二、推进与兑现
- 按实际内容阶段说明：每一段/阶段先做什么，为什么下一步接这个内容。
- 开头重点说明它建立了什么观看理由、问题、期待或关系，不要只贴“悬念式/反常识式”等标签。
- 中间说明信息、故事、例子、冲突、解释或条目如何继续推进。
- 结尾说明是否兑现前面承诺，以及怎样收束。
- 指出明显的拖沓、跳步、重复、承诺过大或兑现不足。

三、核心交付与增量
- 哪些内容是真正的核心交付，哪些只是铺垫或连接。
- 新增的是事实、故事、解释、关系、观点、策展、情绪理解还是其他价值。
- 如果没有可靠依据判断“与常见讲法相比是否更新”，明确写“无法可靠判断”，不要编造。
- 如果内容主要是高质量整理/盘点而不是深层观点，也按实际说明，不强行拔高。

四、关键内容动作与类型特有机制
只分析实际重要的动作，并说明原文位置或对应内容及其当前功能。
可以涉及但不限于：信息释放顺序、材料选择、叙事转折、条目排序、对比、问题设置、表达节奏、口语化、案例、情绪、人物可信度、互动接口等。
必须使用与当前内容类型匹配的分析重点。
不要为了覆盖栏目而罗列技巧名称。

五、评论信号
- 评论中实际出现了哪些值得注意的追问、争议、补充、共同记忆或未满足需求。
- 哪些评论信号与原文的核心交付一致，哪些暴露了原文没有展开的地方。
- 对评论中的事实补充或传闻只标记为“待核实线索”，不作事实结论；不得把评论写成对原文事实的确认、证实或普遍现象的证明。
- 本节应先区分四种语义身份：评论观察（评论里实际出现了什么）、评论事实线索（评论提出了什么待核实说法）、作者观点（原文作者自己的评价或叙事框架）和模型结构分析（这一段在内容内部承担什么作用）。评论观察可以保留情绪词和价值词，但必须说明它属于评论者的表达；评论事实线索必须保留“待核实”身份；作者观点不能被改写成客观事实；模型结构分析不能越级写成传播、互动、留存或其他外部效果。
- 复核重点是来源、主张类型和推理跨度：评论观察不能被推成效果或因果，评论新增事实不能被写成已确认事实，作者判断不能被模型接管为客观结论。不要按单个词建立敏感词黑名单；“共鸣”“成功”“影响”“怀旧”等词是否合适，要看它属于谁的主张以及句子是否越过了证据边界。
- 如果评论没有有效信号，明确写“没有发现有效评论信号”。

六、候选复用原则与边界
最多保留 3 条真正值得后续参考的候选原则；没有则写“无”。
每条必须包含：
- 做法；
- 本篇中的作用；
- 最低必要前提；
- 最明显误用风险。
最后只判断本篇相对于自身内容承诺、实际推进和当前内容类型目标的真实短板或不可复制因素。不得把外部播放/点赞表现、评论数量、系列能否继续、作者资源多少或能否复制成长期账号能力，当成本篇自身短板。不得因为本篇没有采用另一种内容类型的能力，就把它判断为缺点。例如：不得因为人物故事没有专业分析而自动判断深度不足；不得因为盘点没有复杂人物叙事而自动判断结构不足；不得因为解释型内容没有强烈情绪而自动判断感染力不足。没有明确的承诺落差、推进问题或当前类型内部缺陷时，可以明确写“无明显短板”。

content_type 的用途只是归类：discover 记录观察，classify 消费 FROZEN 注册表。classify 不得为了 exact match 强行归入不合适类型，也不得创建新的分类名称；没有匹配就返回 NO_MATCH 或 OUT_OF_SCOPE。

如果本次输入的母样本本身明显命中 domain_context 的领域排除项，这说明上游“领域资格/正式爆款写入 → 拆解调用”之间可能存在不一致：
- analysis_text 只用于返回本次调用的领域冲突诊断，并明确标记“该样本不具备当前领域正式拆解资格”；
- source_content_type 可按输入内容实际类型填写，仅用于本次错误定位；
- 本 Prompt 不得暗示该结果可以作为正式拆解留存。下游必须阻断正式写入；如果该样本此前已因错误资格产生正式拆解，应按系统既有纠错规则清除错误拆解及其派生产物。

【2B 冻结生产规则】
当 domain_context.content_type_lifecycle 为 classify 时，这是正式生产分类，不是开放命名。

一、SOURCE_CONTENT_TYPE 必须直接填写 content_type_registry 中的 canonical_id。不得填写中文名称、自然语言类别、历史 raw type 或自行创造的新名称；没有匹配时只能填写 NO_MATCH 或 OUT_OF_SCOPE。

二、正式生产只能消费 domain_context.content_type_registry 中 status 为 FROZEN 的人工批准类型。observed_content_types、历史 keyword mapping、本文示例和模型记忆都不是生产白名单。若注册表不是 FROZEN，调用应被系统阻断，不能退回自由命名。

三、正式类型的判断优先级是：核心对象、核心内容承诺、主要交付、推进结构，最后才是 canonical_id。必须依据当前 domain_context.content_type_registry 中各正式类型的定义和边界进行判断；人物名称、关键词或本文示例不能替代判断，也不能假设当前 domain 只能使用某一组固定类型。
