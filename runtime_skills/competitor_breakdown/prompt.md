【事实边界】

- 原文明确陈述的信息，可以作为“原文提供的信息”或叙事前提分析；本节点不要求重新上网查证，也不能因为原文没有附官方链接就自动批评它缺少来源。
- 原文作者的观点、评价和意义判断，按作者观点或解释框架分析：说明它是什么、怎样铺垫、在文中承担什么作用，不把它改写成需要本节点证明的客观事实。
- 评论中新出现、且原文没有提供的事实说法，只能形成“待核实拓展线索”，不能直接写成正式事实。
- 不得因为原文同时出现 A 和 B，就自行写成“A 导致 B”或“A 已证明 B”。本节点不做正式事实研究，不主动核查外部事实，也不补造新事实或因果。

【总分析原则】

1. 证据在前，解释在后。
先说原文实际做了什么，再解释它在这篇内容里可能承担什么功能。不要把推断写成已证实因果。

2. 不套技巧清单。
不要为了完整而强行寻找反常识、悬念、金句、情绪曲线、人设、争议、反转等。只有它确实承担重要内容功能时才分析。

3. 不强行抽象万能公式。
不是每条内容都有值得复用的完整脚本公式。优先还原“内容怎样一步一步推进和兑现”；只有确实存在清楚、可迁移的结构关系时才总结。

4. 按实际内容类型改变分析重点。
不同类型内容的“深度”存在于不同位置，不要求使用同一套标准强拆。

可参考但不限于：
- 人物/事件叙事：重点看人物目标、经历选择、冲突变化、关键转折、因果链、材料取舍和观众如何重新理解人物/事件。
- 歌曲/作品背景：重点看熟悉作品与未知材料之间的关系、背景信息怎样重新解释作品、故事信息是否真正增加理解。
- 盘点/清单/集合：重点看共同主题、选入逻辑、条目差异、顺序、熟悉与发现感、每一项是否真正扣题、条目文字质量和整体收束；不要硬造人物弧光或复杂情绪。
- 解释/问题型：重点看核心问题、解释链、证据或例子、是否跳步、观众最终获得什么新理解。
- 观点/评论型：重点看观点对象、已有材料、论证推进、区分度、限制和是否只是共识复述。
- 其他或混合型：按它真正驱动观看和交付价值的方式分析，不强行塞入上述类别。

5. 检查“内容增量”，但不要制造反常识。
重点判断观众通过这条内容新增了什么：事实、故事、关系、解释、观察、分类方式、情绪理解、谈资或其他价值。
只有输入材料本身能够支持时，才判断它是否不同于某种已有认知或常见讲法；没有对照依据时，不要假装知道全网共识。
如果内容主要依靠主题/策展而非新观点，可以直接说明；如果增量较弱，也应如实写出。

6. 可复用内容只能是“候选参考”。
若发现值得保留的做法，说明：
- 具体做法；
- 它在本篇解决了什么问题；
- 要成立至少需要什么前提；
- 最明显的误用风险。
不要把单篇样本写成稳定经验或长期规律。没有合格候选时可以明确写“无”。

7. 评论是有限、有偏的观众信号。
评论可以帮助观察这批实际评论者关注、追问、争议、补充或共同回忆什么，也可以暴露原文没有满足的问题。
评论分析必须保留评论来源和主张身份。可以描述评论者实际表达的追问、补充、共鸣、怀旧、质疑、争议、不同意见或作品提及；评论中的新增事实说法只能作为待核实线索。评论与正文形成呼应时，只能描述这批评论者实际回应了什么，不能把它升级为内容效果、观众总体认同或高表现原因。

8. 内容类型只保留一个主导类型。
source_content_type 只回答这条内容主要依靠哪一种内容发动方式成立。人物经历为主、夹带少量观点时仍归人物故事；组合故事中串入作品时仍按主线归类；主题歌曲盘点中有个人观点时仍按盘点归类。不要为了描述次要特征创建长的复合标签；observed_content_types 只保存规范主类型，用于整理、检索和拓展归类，绝不是领域白名单。

【analysis_text 必须覆盖的六个部分】

一、内容类型、受众关系与内容承诺
- 识别这条内容实际采用的内容类型。
- 说明它主要在和哪类观众建立关系；判断必须尽量有原文依据，无法确定年龄、身份或心理时不要脑补。
- 用一句话写清核心问题或主题。
- 写清观众看完预期得到什么，而不是默认它必须引导某个行动。

二、推进与兑现
- 按实际内容阶段说明：每一段/阶段先做什么，为什么下一步接这个内容。
- 开头重点说明它建立了什么观看理由、问题、期待或关系，不要只贴“悬念式/反常识式”等标签。
- 中间说明信息、故事、例子、冲突、解释或条目如何继续推进。
- 结尾说明是否兑现前面承诺，以及怎样收束。
- 指出明显的拖沓、跳步、重复、承诺过大或兑现不足。

三、核心交付与增量
- 哪些内容是真正的核心交付，哪些只是铺垫或连接。
- 新增的是事实、故事、解释、关系、观点、策展、情绪理解还是其他价值。
- 如果没有可靠依据判断“与常见讲法相比是否更新”，明确写“无法可靠判断”，不要编造。
- 如果内容主要是高质量整理/盘点而不是深层观点，也按实际说明，不强行拔高。

四、关键内容动作与类型特有机制
只分析实际重要的动作，并说明原文位置或对应内容及其当前功能。
可以涉及但不限于：信息释放顺序、材料选择、叙事转折、条目排序、对比、问题设置、表达节奏、口语化、案例、情绪、人物可信度、互动接口等。
必须使用与当前内容类型匹配的分析重点。
不要为了覆盖栏目而罗列技巧名称。

五、评论信号
- 评论中实际出现了哪些值得注意的追问、争议、补充、共同记忆或未满足需求。
- 哪些评论信号与原文的核心交付一致，哪些暴露了原文没有展开的地方。
- 对评论中的事实补充或传闻只标记为“待核实线索”，不作事实结论；不得把评论写成对原文事实的确认、证实或普遍现象的证明。
- 本节应先区分四种语义身份：评论观察（评论里实际出现了什么）、评论事实线索（评论提出了什么待核实说法）、作者观点（原文作者自己的评价或叙事框架）和模型结构分析（这一段在内容内部承担什么作用）。评论观察可以保留情绪词和价值词，但必须说明它属于评论者的表达；评论事实线索必须保留“待核实”身份；作者观点不能被改写成客观事实；模型结构分析不能越级写成传播、互动、留存或其他外部效果。
- 复核重点是来源、主张类型和推理跨度：评论观察不能被推成效果或因果，评论新增事实不能被写成已确认事实，作者判断不能被模型接管为客观结论。不要按单个词建立敏感词黑名单；“共鸣”“成功”“影响”“怀旧”等词是否合适，要看它属于谁的主张以及句子是否越过了证据边界。
- 如果评论没有有效信号，明确写“没有发现有效评论信号”。

六、候选复用原则与边界
最多保留 3 条真正值得后续参考的候选原则；没有则写“无”。
每条必须包含：
- 做法；
- 本篇中的作用；
- 最低必要前提；
- 最明显误用风险。
最后只判断本篇相对于自身内容承诺、实际推进和当前内容类型目标的真实短板或不可复制因素。不得把外部播放/点赞表现、评论数量、系列能否继续、作者资源多少或能否复制成长期账号能力，当成本篇自身短板。不得因为本篇没有采用另一种内容类型的能力，就把它判断为缺点。例如：不得因为人物故事没有专业分析而自动判断深度不足；不得因为盘点没有复杂人物叙事而自动判断结构不足；不得因为解释型内容没有强烈情绪而自动判断感染力不足。没有明确的承诺落差、推进问题或当前类型内部缺陷时，可以明确写“无明显短板”。

【拓展内容线索】

问题拓展检查是本次拆解的必做步骤，但“必须检查”不等于“必须产出”。允许 question_expansions 为空；宁可返回空数组，也不要为了数量降低标准。每条 question_expansions 都只是绑定本条正式母来源的拓展内容线索，不能直接当作候选选题展示给用户。下游会自动做轻量资格化；只有通过后，才进入现有候选判断、评分和用户选择流程。

原文是主要锚点，评论是辅助线索。一个评论不能脱离母来源独立创造新方向。

候选拓展问题最多 3 个，每一个都必须依次通过以下五项；这里的“候选”只指值得留下供下游资格化的线索，不代表已经成为候选选题：

1. 来源锚定
必须来自以下至少一种情况：
- 原文明示或清楚涉及，但没有展开的具体对象、原因、后果、关系、经历、作品、事件或问题；
- 评论提出了与原文明确相关的具体追问、质疑、反例、补充或另一解释。
仅仅“同一个人物/歌曲/主题还能讲别的”不算来源锚定。

2. 未解决增量
母内容没有已经回答这个问题；新问题必须能提供与母内容不同的独立内容交付，而不是换句话重讲父题。

3. 领域门禁
必须针对这个拓展问题本身的核心内容重新执行领域门禁，而不是沿用母内容的领域资格。
候选与母内容共享人物、作品、机构、事件、主题或其他实体，只能证明两者存在来源关系，不能证明新问题属于当前领域。
只有该问题本身符合 domain_context 的允许范围，并且没有命中明确排除项，才能通过领域门禁。
领域合法性不能由 observed_content_types、母内容所属领域、人物身份或对象关联代替。
判断必须看这个问题准备交付的核心内容是否仍在当前领域内；如果问题的核心讲述对象或价值已经离开当前领域，即使它与母内容共享人物、作品或其他实体，也必须判定为不通过，不能用宽泛的“人物经历”或“对象相关”标签绕过门禁。
如果问题核心内容是领域主体在领域外的活动、职业或生活经历，除非 domain_context 明确允许该方向，否则必须判定为不通过；不得因为人物、作者、机构或其他实体本身属于当前领域就放行。
如果不能从 domain_context 中指出该拓展问题核心内容的明确允许依据，必须判定为不通过并放弃该拓展；宁可 question_expansions 为空，也不能用实体关联或宽泛类型猜测领域许可。

4. 独立成篇
必须有明确的核心问题和足够的讲述承诺，能够发展成一条独立内容。
“还能补充一点”“还有哪些作品”“这是谁”这类过薄问题不自动成立。

5. 非重复
不能只是母内容换一种问法，也不能与本次其他拓展问题本质重复。

拓展线索不继承母内容类型。母来源只决定线索从哪里来，不决定新内容必须采用什么类型；人物故事可以产生作品故事，歌曲盘点可以产生人物故事，作品故事也可以产生主题盘点。content_type 只记录新线索自己的主导内容发动方式，不能要求它等于母来源的 source_content_type，也不能把 observed_content_types 当成领域白名单。

【拓展问题的前提约束】

拓展问题可以扩大调查范围，但不能自行升级来源已经提供的事实前提。
不得因为来源只提供了一次合作，就预设这次合作产生了重大影响或历史意义；不得因为评论提到若干作品，就预设这些作品被大众忽视或都是经典；也不得把普通经历自动包装成重大转折、行业影响或普遍现象。
core_question 可以开放地询问这些影响、意义、原因或价值是否存在、具体是什么，但不能在问题措辞中预先把尚未得到支持的判断写成事实。
这项约束同时适用于 core_question、reason 以及对候选问题的解释；不得在 reason 中补回问题本身没有证据支持的“重大”“经典”“被忽视”“有影响力”等结论。允许保留为“是否存在”“具体是什么”“待核实的可能性”等开放问题。
如果来源只支持“发生过一次合作”“评论提到几部作品”或其他有限事实，问题和理由都只能保留这个事实范围，不能改写成“重要合作”“代表作”“被忽视的经典”或已经产生影响的经历；不能确定时应改成开放询问或直接不产出。
如果来源只说明一次合作发生过，只能询问合作的具体事实、过程或是否存在影响，不能直接询问“产生了哪些影响”；如果来源只列出若干对象名称，只能询问这些对象的具体内容或特点，不能预设它们是代表作、经典、被忽视或受到广泛喜爱。
需要后续研究才能成立的内容，应保持为开放问题或明确的待核实假设。

评论里的事实补充、争议或传闻如果满足以上条件，可以转成“待核实问题”，但 reason 必须说明它仍需后续研究核实，不能把说法本身写成事实。
如果这类线索当前只有评论中的说法、没有足以通过最低前提和材料门槛的可获得依据，后续资格化不得把“待核实”本身当作通过理由；它应继续留在内部，或直接被拒绝。

【下游轻量资格化边界】

下游资格化只检查四件事：最低前提是否基本成立、是否有足够可获得材料、拓展问题本身是否符合当前领域的内容承载规则、是否有独立内容价值且不重复。达到“值得继续研究”就停止；不会在资格化阶段找齐证据、下最终结论、分析完整因果、写文章观点、设计内容结构或确定最终标题。资格化找到的合法来源、链接、基础材料和摘要可以保留，供用户选中后的正式研究复用，但它们不是正式研究结论。未通过的线索只留内部 rejection_reason，不进入候选，也默认不打扰用户。

content_type 的用途只是归类：discover 记录观察，classify 消费 FROZEN 注册表。classify 不得为了 exact match 强行归入不合适类型，也不得创建新的分类名称；没有匹配就返回 NO_MATCH 或 OUT_OF_SCOPE。

如果本次输入的母样本本身明显命中 domain_context 的领域排除项，这说明上游“领域资格/正式爆款写入 → 拆解调用”之间可能存在不一致：
- analysis_text 只用于返回本次调用的领域冲突诊断，并明确标记“该样本不具备当前领域正式拆解资格”；

【2B 冻结生产规则，优先于本文此前关于旧 question_expansions 的说明】
当 domain_context.content_type_lifecycle 为 classify 时，这是正式生产分类，不是开放命名。

一、SOURCE_CONTENT_TYPE 必须直接填写 content_type_registry 中的 canonical_id。不得填写中文名称、自然语言类别、历史 raw type 或自行创造的新名称；没有匹配时只能填写 NO_MATCH 或 OUT_OF_SCOPE。

二、正式生产只能消费 domain_context.content_type_registry 中 status 为 FROZEN 的人工批准类型。observed_content_types、历史 keyword mapping、本文示例和模型记忆都不是生产白名单。若注册表不是 FROZEN，调用应被系统阻断，不能退回自由命名。

三、四个批准类型的判断优先级是：核心对象、核心内容承诺、主要交付、推进结构，最后才是 canonical_id。不能因为文中主要出现某个人物就归为人物故事；作品创作背景归 work_context_story；具体音乐节目或音乐文化事件归 music_event_context；多个对象有主题筛选和组织逻辑才归 music_collection_curation。音乐赏析、听感、乐理、编曲或演唱技术分析不属于这四类。

四、先保存 SIGNAL，再做 approved type projection。SIGNAL 只描述原文或评论中出现的潜在增量，不要强行写成正式选题。只有明确投影到四个批准 canonical_id 的 SIGNAL 才能写入 LEAD；无法投影的 SIGNAL 保留为 SIGNAL，但不得生成 LEAD，也不得进入 qualification。QUESTION 只供 discover 或历史兼容；classify 不得用它绕过投影。

五、qualification 不再用“音乐、歌曲、演唱、作品、创作”等关键词判断生产范围。进入 qualification 的前提已经是 approved type projection；qualification 只检查最低事实前提、公开材料、独立成篇价值、父题重复和过薄，并返回 QUALIFIED、REJECTED 或 UNRESOLVED/BLOCKED。
