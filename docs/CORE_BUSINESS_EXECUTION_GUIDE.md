# 内容业务核心包｜业务运行说明

## 1. 使用范围

本说明按实际业务顺序指导一次内容工作：从素材发现、选题选择、研究、写稿到文案和音频交付。视频制作和视频发布不属于当前系统；用户完成外部发布后，发布登记和授权数据回流属于音频交付后的独立反馈阶段。

它只说明业务如何运行，其他配套机制不在本说明范围。

## 2. 开始前要明确的内容

每次工作至少确认：

- 服务哪个账号和领域；
- 是日常发现，还是用户主动给出的方向；
- 用户想解决的问题或对象；
- 已有的链接、文件和来源材料；
- 时效、风险和表达方面的特殊要求。

信息不足时，系统应说明缺什么并等待补充，不能为了凑数量自行编造方向。这里要分清几种情况：用户只是给方向、线索、链接或没有说清的问题，先补充信息或形成候选；用户明确下达一个正式选题，且已说清账号和领域、核心问题以及本次范围或要求，可以直接建立正式选题；用户直接指定人物，则进入人物探索，不把人物名字当成已经成立的正式选题；用户只指定单首歌或一张专辑，则进入作品探索，先确认作品背后的故事和材料能否支撑完整讲述；用户直接给出一组歌，则按盘点内容处理，不拆成多次作品探索。盘点内容必须先说清这组歌共同要讲的问题或盘点角度；只有歌曲清单、没有共同理由时，只是方向，需要补清。歌单只是研究起点，不是锁死的最终范围；发现不合适的歌时，Agent 在对话中说明情况和建议，由用户决定是否删掉或换歌。盘点通常以 10 首为主，不少于 10 首，需要时可以更多；研究可以形成排序作为参考，但不自动变成最终排名，默认不排名，确有需要时才采用排序；不设“某一段时期”这一独立入口。

### 新领域或新账号怎样开始

运行本地冷启动配置入口后，在浏览器打开 `http://127.0.0.1:8765/`。页面会按顺序完成：

1. 验证本次浏览器页面确实能收发正式人工决定；
2. 选择复用已有领域，或比较已有边界后明确新建独立领域；
3. 填写抖音自营账号以及 10—20 个必需的抖音对标账号；优先选择已经持续发布、历史内容充足的成熟账号，不选择刚起号或内容太少的账号；当前不显示或接受其他平台；
4. 预览系统整理后的正式配置并由用户确认；
5. 自动登记全部账号，显示真实启动前仍缺少的采集环境、登录状态或模型配置；
6. 所有检查通过后，由用户点击启动；每个对标账号自动完成历史采集和高信号筛选；全部账号完成筛选后，系统立即从高信号作品原文提取话题标签，不依赖拆解结论，也不调用模型，并使用确定性规则统一过滤人名、组合名、机构名、平台通用标签、限时活动标签、低重复证据项和重复项，形成整版领域标签库；
7. 用户可以在整版标签库中直接删除、编辑，并一次确认整库；点击删除后标签立即离开正式待审列表，不提供恢复切换，编辑内容在页面自动刷新期间保留。与此同时，爆款转写、评论、逐条拆解和账号注册继续自动执行，不受标签审核阻断。每个账号完成全部材料后自动注册，不设置账号确认；已完成拆解只按类型保留和检索，不自动归纳成领域经验；
8. 冷启动资料完成后立即进入首轮日常运营；以后每天 08:00 自动采集抖音对标账号、轮换搜索已启用标签、生成候选前十。页面持续展示结果，用户选择候选后立即生成研究方案。

启动命令为 `python -m scripts.agent_platform.cold_start_config_server`。日常安排、失败留痕和候选展示由同一个本地入口承载，不再要求用户另行启动旧定时脚本。页面不要求填写关键词、内容形态、受众文案或评分权重；这些内容在后续材料形成后再按正常人工确认处理。

作品探索不是按字数凑时长。它需要有明确问题、足以支撑至少 3—5 分钟完整讲述的可靠材料和清晰讲述方向；材料不足时如实说明缺口或停止，不能用空泛感想凑篇幅。具体查什么、怎样组合材料和怎样判断讲述效果，交由 Agent 在自然对话中处理，不设固定公式。

作品探索在正式研究之前，用于判断是否值得讲、讲什么并保留已取得材料。用户确认研究方案后，正式研究按方案推进，并在合适时复用已有材料，避免无意义的重复采集；具体怎样检索和补充由 Agent 判断。

作品探索通过后，Agent 以判断最强的方向为主，并可简短提示其他可行方向；用户通过自然对话决定采用、调整或补充。用户确认的方向才形成正式选题，不把这些对话选择拆成固定的平行流程。

## 3. 素材变成候选选题

### 获取和整理

系统从已接入的真实来源接收公开素材，也可以接收用户给出的链接、文件和方向。每份素材保留来路、时间、领域关联和可追溯标识。

重复、无关、过期、材料不足或风险不明的素材可以被排除，并说明原因。

### 呈现候选

合格素材会被整理为候选选题。用户看到的候选应包含：要回答的问题、谁会关心、为什么值得讲、可用材料、主要不足、风险和可选角度。

用户可以选择、拒绝、暂缓或要求换角度。被选择的候选成为正式选题；用户明确直接下达的正式选题不必先经过候选。直接下达必须保留用户指令、已有或缺失材料、时效、风险和与已有选题的关系；用户指令不是事实依据，后续仍须研究核实。不设通用的每日选择数量硬上限；由候选池的合并关系、评分排序和人工选择控制优先级。没有合格选题时可以不选。

## 4. 正式选题进入研究

候选被选择或用户直接下达正式选题后，系统立即生成研究方案，不留下“已经选定但尚未开始”的积压状态。用户确认或退回的是研究方案，不是重复确认已经下达的选题；只有研究方案确认后，才开始正式研究。

### 看研究方案

系统先给出研究方案。用户主要确认：

1. 这次究竟要回答什么问题；
2. 哪些说法需要验证；
3. 会使用和避开什么材料；
4. 研究到什么程度可以停止。

方向不对、范围太大或材料边界不合适时，用户退回方案并说明调整方向。通过后才开始研究。

### 看研究结果

研究结果应清楚展示可成立结论、材料依据、事实与推断的区别、争议和限制，以及可选讲法。正式研究只使用允许的网页、文件和研究材料；视频、音频、转写、评论和视频平台链接不能作为正式研究来源。

用户可以通过、退回补充、缩小问题或取消。关键依据不足时，不能进入写作。

## 5. 研究变成内容计划

研究通过后，系统给出内容计划。用户重点确认：

- 观众听完应该得到什么；
- 开头是否值得听；
- 内容怎样一步步推进；
- 关键材料是否放在合适的位置；
- 结论是否符合账号方向；
- 有哪些风险或不确定性需要保留。

计划不对时，退回计划或研究；不要让下游文案硬补上游问题。

## 6. 初稿、修改和审核

### 初稿

初稿建立在已通过的内容计划和研究结论上。用户可以确认、提出具体修改、要求换一种讲法，或要求回到研究补材料。

### 优化

优化处理整体表达：开头是否能带人进入，叙事是否持续推进，材料是否好懂，信息密度是否合适，口播是否自然。

用户直接改稿时，系统应保留改前改后版本，作为理解账号表达偏好的材料。

### 审核

审核时确认有没有越过事实边界、遗漏核心承诺、不适合账号或领域的表达、相似风险，以及是否可以成为最终文案。

用户确认后的版本才是最终文案。

## 7. 当前交付内容

用户确认最终文案后，系统使用已经由用户确认的声音配置生成音频。长口播稿自动分段生成；音频必须同时保留声音配置、分段和生成参数，并先通过文件完整性检查和本地回听转写核对，再交用户试听确认。

用户可以只退回音频重新生成；如果试听时发现事实、立场或文案边界问题，则退回内容审核环节形成新版本。只有用户确认音频后，最终文案、标题、声音配置、音频版本和审核结果才组成正式交付。本地素材转写与文案转音频仍是两种独立能力，不能混用。

## 8. 音频交付后的独立反馈链

音频交付是内容生产主链的结束，但不是整个设计的结束。用户完成外部发布后，可以由用户手动登记外部视频，确认它对应的文案和音频版本；系统随后只读取获授权的发布后数据，按 P0—P7 保存观察和缺失，并在 P7 形成复盘与待审核反馈。

系统不生成视频、不发布视频、不自动发送，也不负责评论区运营。发布登记和 P0—P7 观察只记录用户已经完成的外部事实，不能绕过用户确认，不能与对标账号的 D0—D7 数据混在一起，也不能自动把一次数据表现变成长期规则。

系统内的人工复盘至少区分：

1. 选题是否有真实受众关切；
2. 开头、叙事和材料组织哪里有效或失效；
3. 哪些结论有依据，哪些仍无法判断；
4. 用户是否认可内容方向和表达；
5. 发布后的外部条件是否影响了表现。

## 9. 经验怎样用于下一次内容

用户改稿、实际采用和人工复盘都可以形成经验线索。经验要说明适用条件、可能好处、风险和依据。

下一次内容计划只考虑当前任务相关的少量经验。用户可以采用、拒绝或要求调整。经验是否长期保留、暂停或修改，仍由用户确认。

账号表达偏好与跨账号通用经验分开保存；一个账号喜欢的表达不能自动套给另一个账号。

## 10. 常见业务异常

| 情况 | 处理方式 |
| --- | --- |
| 来源无法追溯或材料不足 | 说明缺口，等待补充或关闭线索 |
| 候选不值得做 | 拒绝、暂缓或换角度 |
| 研究无法证明关键结论 | 缩小结论、补材料或取消 |
| 内容计划与用户想法不一致 | 退回计划，重新明确承诺或路线 |
| 稿件新增重要事实 | 回到研究或计划补足 |
| 文案有风险或相似问题 | 退回相应环节并创建新版本 |
| 模型结果无法使用 | 保留原因，等待人工决定是否以同一明确配置重新处理 |
| 外部发布数据无法判断 | 当前系统不接入这类数据；如未来需要，另行确认设计和入口 |

## 11. 使用模型时应知道的事

模型只在明确用途和配置下工作，不会自行换模型、换服务或降低能力。模型可以帮助理解材料、组织研究、提出候选、写稿和审核，但不能代替用户选择选题、确认最终稿或决定长期经验。

模型结果不清楚、不符合材料或违反边界时，应停在当前环节。

## 12. 一次内容工作的结束

一次内容工作在以下条件满足时结束：

1. 用户确认最终文案和标题；
2. 使用已确认声音配置完成音频生成、回听核对和用户审核；
3. 最终文案、标题、声音配置和音频能够对应到它的来源、研究、内容计划、稿件和审核决定。

外部发布表现不属于当前系统；经验沉淀只使用系统内已经确认的材料和人工判断，不阻塞当前内容交付。
