# 日常运营实施阶段

本阶段在冷启动完整收口后启用。日常运营必须复用冷启动建立的账号、基线、爆款、标签、经验和 Obsidian 关系，不另建一条临时链路。

## 本阶段要打通的完整链路

1. 每日由一次统一自动触发拉起日常入口（目前为中国时间 09:00）；项目收到调用后立即执行，不保存、不计算、也不二次校验调度时间。一次触发只负责检查当天各正式领域，并为每个领域按 domain + business_date 找到或建立唯一正式 daily run。所有 daily run 共用一个执行槽并严格串行；failed 或 stopped 的领域不自动重试，但其它领域可以继续。用户明确继续时恢复原 daily_run_id，只处理该 run 尚未完成的部分；completed 才表示该领域当天日常完成。当天全领域是否完成由各领域 daily run 状态推导，不建立全局 daily lifecycle。正式执行、首次执行和调度测试都调用同一个项目入口；冷启动完成后由外部调度器安排下一次正式调用。
2. 复用同一个采集登录环境追踪全部已确认抖音对标账号。新视频按 D0—D7 留存和判断；只有形成正式爆款记录后，才进入备料、转写、评论、拆解和问题拓展来源。
   备料完成与拆解完成必须分别判断。拆解失败时保留已经完成的下载、转写和评论，人工在当天明确继续只补缺失拆解，不重新采集；第二天的自动日常任务不得擅自重试前一天失败项。
3. 日常对标内容只负责持续追踪和爆款判断，不直接形成候选。候选入口读取历史爆款库中的历史存量爆款和日常新增爆款、达到点赞门槛的标签搜索结果、带正式母来源的问题拓展和人工保存方向；来源、重复、领域、时效和风险先处理，再形成候选。
   领域热点转选题单独运行，音乐停用，泛科普等适用领域保留。综合榜单不是转选题的前置步骤。
4. 每天轮换最久未搜的 3 个启用标签，每个只搜 1 页。已登记对标账号的视频直接去重；未登记账号在 30 天内出现 3 条不同合格视频后，展示最近 10 条供人确认，确认后立即走完整注册。
5. 同题同角度合并支持材料并重评；同题不同角度分别保留并建立关系。候选统一通过 candidate_priority Skill 由当前 Agent 依据全部合并候选与已有材料给出 0—100 制作优先级、理由、引用及限制，Core 保存排序；不再使用字段映射或六维权重。缺失或材料已变化的评分不得完成候选榜，原日报等待 Agent 提交当前判断；零候选直接完成。
6. 每日前 10 只是优先级展示，不是处理上限或每日产量限制。候选可一次选择一条或多条；选择本身就是正式选题确认，随后立即生成研究方案，只有研究方案仍需人工确认。
7. 明确直接下达的正式选题跳过候选和前 10，但必须留存原始人工来源。人物、单个对象和对象集合分别进入人物探索、对象探索和集合盘点探索，不得误当作直接正式选题。
   三类探索必须继续经过同一套正式材料留存入口；具体采集器、平台、数量和目标时长由当前领域配置决定，不能把某个领域的专属规则套到其他领域。探索过程中不逐条要求人确认，只有形成材料支持的最终方向后停一次；用户确认方向后立即建立正式选题并生成研究方案。
8. 标签提取和维护都不调用模型，不自动暂停或删除；以整库形式交人编辑、删除和一次确认。
9. 日常发现链不自动进入发布登记或 P0—P7 反馈链；用户完成外部发布后，发布登记与 P0—P7 观察只能从独立的用户确认入口开始。自营账号的每日采集和同期基线也必须独立于对标账号保存；当前对标日常链已实现，自营日常采集尚未接通。
11. 每次正式变化后自动更新本地知识镜像和双向关系。镜像只用于浏览和追溯，不反向修改正式业务状态。
11. 自动日常运行、候选选择、人工来源、特殊探索和标签库正式动作执行前，都重新核对当前日常小型契约；不一致时直接阻断正式写入。

## 本阶段检查重点

- 日常对标追踪是否与候选生成分开；历史存量爆款与日常新增爆款是否都通过正式爆款库进入候选；
- 标签搜索是否先排除已登记对标账号，并且单条点赞数达到 10000 后才进入候选判断；
- 问题拓展是否绑定明确母来源，且不能继续从另一条问题拓展派生；
- 音乐热点停用是否生效，其他领域是否可独立转题，历史记录是否保留；
- 前 10 是否只负责展示，是否不存在每日硬限制；
- 候选选择后是否直接生成研究方案；
- 标签维护是否完全不调用模型；
- 是否没有把视频生成、视频发布混入日常发现；发布登记和 P0—P7 是否只从独立用户确认入口开始；
- 自营账号是否已经进入独立每日采集和同期基线；没有真实发布数据时是否仍按“上游尚未走到”记录，而不是判定设计不存在；
- 中断、风控或失败后是否停止自动重试并给出明确状态；
- 日常爆款是否不会把“备料完成但拆解失败”伪装成整条完成，人工继续时是否只补当天缺失部分；
- 正式写入是否经过运行护栏，知识镜像是否随正式关系更新。

## 正式 daily run 边界

- 每个正式领域、每个业务日期最多一个正式 daily run；executor execution 不是 daily run。
- daily run 只使用 running、failed、stopped、completed 四种生命周期；进程中断落入现有 failed/stopped 语义，不建立新的中断状态。
- failed 或 stopped 不自动重试；其它领域可以继续串行执行；用户继续时使用原 daily_run_id。
- 采集、素材准备、拆解和候选发现优先复用已有正式完成结果，只处理该 daily run 尚未完成的部分。
- 账号级 collection 是否完成，以 daily_run + account 的正式完成事实为准；audit 不参与业务恢复判断。
- 测试和验证运行不能冒充正式 daily run；通知状态不参与 daily run 状态判断。
## 问题拓展执行点

正式爆款完成拆解时，同时生成问题拓展。原文是主要依据，评论只补充观众疑问和争议，不能单独生成问题。候选筛选只读取已经绑定到爆款拆解的问题拓展，不在候选阶段重新从评论发散。

## 热点接入边界

领域热点转选题与综合榜单独立运行。音乐停用，泛科普等适用领域的热点经现有热点来源入口进入公共选题流程，不要求人工先挑选榜单。旧专用生成分支不恢复；沿用统一 Agent 执行和 Core 写入。当前日常定时来源集合不因此自动扩大。

## 2026-09-09 选题流程对齐

普通线索默认由当前 Agent 搜索理解，完整题目可以保留，不增加独立候选资格环节。Core 传入已有全文与当前领域规则，成题结果保存实际已读材料；音乐明确排除专业乐评和技术分析，其他领域不继承音乐限制。只有成形候选进入同角度合并与制作优先级比较，未成形线索记录不转题原因。

日常与 MCP 共用候选保存入口。待外部处理的来源从本批现有输入装配中读取，逐项提交后续接下一条，全部处理后才进入评分与榜单完成。旧输入包和旧输出版本不能与新流程混用。真实材料隔离验收见本次验收记录；此前单独的评分回放不能证明完整选题质量。
