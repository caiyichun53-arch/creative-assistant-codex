# 实施护栏阶段

## 目的

本阶段只建立项目实施时使用的本地检查。普通讨论、方案澄清和日常问答不启用。

## 固定边界

- 完整设计只用于建立或修改阶段执行文档，不由钩子反复读取。
- 每个阶段只有一份小型可执行契约；代码实施和真实运行读取同一份契约。
- 实施前只识别当前阶段并检查该阶段契约。
- 实施中只拦截文件写入，只检查本次改到的阶段；普通只读命令不触发检查。
- 写入工具传入完整磁盘路径时，必须先还原成项目内路径再判断所属阶段；同一个公共文件可以属于多个阶段，但当前阶段必须是登记的所属阶段之一。
- 项目内尚未登记所属阶段的文件不得在实施任务中直接写入，必须先把它纳入明确阶段。
- 当前阶段可以只修改阶段指针以切换到下一项已登记阶段；切换后的下一次实施写入必须按新阶段检查，不得因指针本身只属于护栏阶段而形成死锁。
- 各业务阶段共用的本地确定性验证器必须登记为所有业务阶段的公共文件，保证阶段契约与对应检查可以在同一阶段同步修改。
- 实施后只运行当前阶段的本地确定性检查，不调用任何模型。
- 钩子脚本不得读取完整设计文档、旧实施基线或历史规则目录。
- 每个 Codex 任务使用独立的实施状态；普通聊天或其他任务不得覆盖正在实施的任务状态。
- 写入后或结束检查要求 Codex 自动继续修正时，续做提示必须继承原任务的实施状态，不得被当成普通讨论绕过。
- 钩子是否生效必须用 Codex 自动触发留下的事件记录证明，手工运行不算。

## 完成条件

- 任务开始、写入前、写入后、任务结束四类事件均可自动留痕。
- 写入前和写入后不再匹配普通命令。
- 当前阶段检查只读取阶段登记、当前阶段指针和该阶段的小型契约。
- 修改钩子后重新完成 Codex 信任确认，并取得自动触发证据。
