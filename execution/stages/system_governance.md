# 系统基础治理阶段

## 目标

把模型判断、确定性执行和正式数据保存彻底分开，并让构建期与运行期都自动阻止越界。

## 本阶段任务表

| 任务 | 当前状态 | 验收边界 |
| --- | --- | --- |
| 原子 Skill 基础规则 | 已落实 | 新增业务模型判断必须登记为独立 Skill；Skill 不得读写正式数据或改状态。 |
| 脚本／核心边界 | 已落实 | 采集、转写、计算、保存、调度、重试、状态和人工决定均留在系统执行层。 |
| 构建期自动拦截 | 已落实，自动触发取证完成 | 实施写入中新增业务流程直连模型调用会被拦截。 |
| 运行期自动拦截 | 已落实，自动阻断取证完成 | 尚未改为原子 Skill 的内容生产模型节点会被正式运行阻断。 |
| 爆款拆解 | 已改为独立 Skill | 首次注册与日常拆解共用同一 Skill；保留原有材料范围和输出结构。 |
| 对标拆解 | 已改为独立 Skill，质量已认可 | 一条视频一条留存；只用于口播文案和内容打法的整理、检索与追溯，不自动归纳领域经验。 |
| 双周学习建议 | 已改为独立 Skill | 只产出建议，不得自动改评分、经验或标签。 |
| 内容生产模型节点 | 已审计并暂时阻断 | 现有研究方案、深度研究、内容计划、成稿、优化、去 AI、审阅仍通过旧的通用模型入口；在逐项改为原子 Skill 前不允许正式运行。 |
| Skill 质量对照 | 对标拆解已认可；其他未认可能力继续阻断 | 使用同一批冻结材料对照旧输出；未通过结构、证据和人工抽查，不切换正式节点。 |
| 正式运行数据迁移 | 已落实 | 已复制、校验并切换；新服务只使用项目外运行区。 |
| 自动触发证明 | 已完成 | 已有 Codex 自动事件和正式运行拦截记录。 |

## 不能做的事

- 不把自然对话、临时表达调整或资料取舍写成僵硬流程。
- 不以质量未知的新 Skill 直接替换当前正式节点。
- 不为兼容而保留新旧正式数据根目录同时写入。
- 不因迁移而删除当前正式数据；旧位置的处置必须在新位置验证后另行明确。

## 完成条件

只有任务表全部完成，且自动拦截与质量对照都有可核验记录，才能把本阶段标为完成。
